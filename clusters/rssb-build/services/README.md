# Build-phase services, RSSB build cluster

PostgreSQL, Kafka and Redis inside the cluster, for the build phase only (plan, D36): the
apps are proven on real nodes before RSSB's shared servers take over. Applied by
`../apps/build-services.yaml`; the operators come from `../apps/cnpg.yaml` and
`../apps/strimzi.yaml`.

| Service | How | Address inside the cluster | Survives one lost node? |
|---|---|---|---|
| PostgreSQL 18 | CloudNativePG `Cluster`, 1 primary + 1 replica | `postgres-rw.platform-services.svc:5432` | yes (automatic failover) |
| Kafka 4.3 | Strimzi, 3 KRaft nodes, replication 3 | `kafka-kafka-bootstrap.platform-services.svc:9092` | yes (two in sync) |
| Redis 8 | one StatefulSet pod, append-only file | `redis.platform-services.svc:6379` | no: a pause until the pod returns |

Storage is MicroK8s' hostpath class: a pod moved to another node starts empty and is
rebuilt from its peers. Right for a build cluster, wrong for production data.

## Who may connect

`network-policy.yaml`: the services among themselves; the PostgreSQL operator
(`cnpg-system`); Crossplane's providers (`crossplane-system`, ports 5432 and 9092); KEDA
(`keda`, 9092, for consumer lag); and every app namespace (label `product`), ports 5432,
9092 and 6379. App namespaces get the matching egress rule from `platform/policies`
(`allow-platform-services`, towards namespaces labelled `platform/role: services`).

## Secrets (sealed, this cluster's certificate only)

Written by `scripts/seal-build-services.sh`, values generated by `openssl`, never shown:

| Secret | Keys | Read by |
|---|---|---|
| `postgres-admin` (`kubernetes.io/basic-auth`) | `username`, `password`, `endpoint`, `port` | CloudNativePG (the `crossplane` role) and provider-sql (`../crossplane/platform-postgres.yaml`) |
| `kafka-admin` | `password`, `credentials` (brokers + SASL, JSON) | Strimzi (`kafka-user.yaml`) and provider-kafka (`../crossplane/platform-kafka.yaml`) |
| `redis-users` | `users.acl` (password hashes only) | Redis at start |

Each app environment named on the script's command line also gets its `REDIS_URL` sealed
into `apps/<product>/envs/<env>/secrets/rssb-build/backend-secrets.sealed.yaml`.
Sealed values cannot be read back, so a re-run regenerates every password: the operators
and the providers pick the new ones up by themselves (same Secrets), the apps roll when
their sealed file changes.
